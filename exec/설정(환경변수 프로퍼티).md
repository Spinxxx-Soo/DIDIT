## 3. 설정(환경변수/프로퍼티)

### 3.1 환경 변수/프로퍼티 목록(필수/선택, 보안등급 포함)

**보안등급 기준**

- **공개(Public):** 외부 공개해도 무해한 값(예: 타임존, 플래그)
    
- **내부(Internal):** 외부 공개 비권장(도메인/호스트/내부 구조 정보 등)
    
- **비밀(Secret):** 키/토큰/비밀번호 등 유출 시 위험한 값

**정리 메모(운영 문서용 권장 문구)**

- `OPENVIDU_*`는 **미디어 기능 사용 시 필수**이며, 미사용 시 해당 값 없이 운영 가능하다.
    
- `GITHUB_*`는 **GitHub OAuth 로그인 사용 시 필수**이며, 미사용 시 해당 값 없이 운영 가능하다.
    
- `VITE_BACKEND_URL`은 운영 환경에서 프론트가 API를 호출해야 하므로 **운영 시 사실상 필수**로 취급한다.
    
- `REDIS_HOST/PORT/PASSWORD`는 서버와 AI에서 모두 사용될 수 있으므로, **서로 다른 실행 환경에서 주입되도록 관리**한다(컨테이너 분리/CI 변수 분리 등).

## 3.2 설정 주입 방식(.env/CI/OS 등) 및 샘플 파일 안내

### 3.2.1 Docker Compose

- Compose는 **동일 디렉터리의 `.env` 파일** 또는 **OS 환경변수**를 읽어 컨테이너 환경변수로 주입한다.
    
- **로컬 개발**: `apps/server/.env`를 기준으로 구성한다.
    
- **배포/운영(`infra/docker-compose/`)**: `.env` 샘플이 기본 제공되지 않으므로, 아래 방식 중 하나로 주입한다.
    
    - 운영 서버에 `.env` 직접 생성
        
    - CI 변수/GitLab 변수로 주입
        
    - 서버 OS 환경변수로 주입
        

### 3.2.2 Spring Boot

- 기본 설정은 `application.yml`, 운영 오버라이드는 `application-prod.yml`로 관리한다.
    
- `${ENV:default}` 형식으로 환경변수 치환을 사용하며, 아래 우선순위로 값이 덮어써질 수 있다.
    
    - OS 환경변수 / 컨테이너 env / CI 변수 → Spring Boot 프로퍼티
        

### 3.2.3 프론트엔드(Vite)

- `apps/client/.env` 사용
    
- `VITE_` prefix가 붙은 값만 빌드에 포함된다.
    
- Docker 빌드 환경에서는 아래 중 하나로 처리한다.
    
    - 빌드 컨텍스트에 `.env` 포함
        
    - 빌드 인자/CI 변수로 대체 주입
        

### 3.2.4 AI(FastAPI)

- `apps/ai/src/common/settings.py`에서 `.env` 로딩을 지원한다.
    
- 로컬/운영 모두 `apps/ai/.env`를 생성하여 주입하는 방식을 권장한다.
    
- OS 환경변수로도 동일 키 주입이 가능하다.
    

---

### 3.2.5 샘플 파일 위치

- **서버:** `apps/server/.env.example'
    
- **클라이언트:** `apps/client/.env`
    
- **AI:** 샘플 없음 → 필요 시 `apps/ai/.env` 직접 생성하여 사용
